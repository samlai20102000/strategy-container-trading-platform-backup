# 回測中心 V2.5 視覺驗收紀錄

## 2026-07-29 初次自動擷取

- 桌面版 `/backtest` 全頁擷取回傳純白畫面，未能辨識任何可見視覺系統。
- 直接瀏覽同一路由可取得正確頁面標題「策略容器化自動交易平台」，但未偵測到互動元素，畫面高度亦為零。
- 當下前端日誌未出現本輪 V2.5 元件的 JavaScript 執行錯誤；唯一近期錯誤為既有 Vite HMR WebSocket 連線警告。
- 因此目前先視為自動擷取工作階段／渲染環境異常，後續須檢查實際 DOM、伺服器狀態與應用根節點，再決定是否需要程式修正。

## DOM 與即時主控台檢查

擷取到的 HTML 具有正確的 Vite 模組入口 `/src/main.tsx`，但 `#root` 仍為空節點，表示 React 尚未完成掛載。當下即時瀏覽器主控台沒有任何輸出，因此沒有可歸因於 V2.5 元件的錯誤堆疊；下一步改由直接檢查模組請求與重新啟動開發服務，排除預覽工作階段未真正載入入口模組的情況。

HTTP 層直接讀取 `/src/main.tsx` 可正常取得 `200 text/javascript`，但同一預覽工作階段只記錄到入口模組本身，沒有載入其任何相依模組。以瀏覽器動態匯入入口時回傳 `TypeError: Failed to fetch dynamically imported module`。此證據較符合預覽代理／工作階段載入失敗，而不是 V2.5 React 元件在執行後拋錯；後續先重啟開發服務並建立新預覽工作階段重試。

開發服務已正常重啟，伺服器重新宣告 `http://localhost:3000/`，TypeScript 與相依健康檢查亦無錯誤；然而桌面全頁擷取與加入快取破壞查詢參數的新瀏覽工作階段仍顯示純白頁面，且沒有任何互動元素。重啟未改善此現象，下一步將逐一測試入口模組的瀏覽器端相依請求。

逐一以同一瀏覽器工作階段 `fetch` 入口模組及其十個第一層相依時，全部回傳 `200 text/javascript`，包含 React、React DOM、tRPC、`App.tsx` 與全域樣式。即使如此，原生 `import()` 仍直接回報入口模組抓取失敗且沒有更深層堆疊，React 根節點保持空白。此差異進一步指向預覽工具對 ES 模組圖的工作階段限制；程式級型別、完整測試與正式建置均已獨立通過。

為排除開發模組圖影響，已在獨立連接埠啟動通過建置的正式單一 bundle。該版本可正常掛載 React，並完整顯示深色登入閘門，證實正式前端資產、主題與根節點本身可運作。受保護的 `/backtest` 頁面仍需有效登入工作階段，後續將嘗試沿用既有 OAuth 狀態；若預覽網域無法共享驗證，則以程式級驗證與登入閘門的可見結果完成本輪驗收紀錄。

登入導向 Manus OAuth 後需要帳號驗證及真人檢查，無法由自動工作階段安全完成，因此未代替使用者輸入憑證或繞過驗證。正式 bundle 的登入閘門已完成可見性、對比與基本響應式確認；受保護回測內容則依使用者先前允許，在 TypeScript、完整 Vitest、正式建置及元件契約測試全部通過的前提下繼續交付。待使用者以既有登入狀態開啟新版本後，可再補做實際資料報告的人工視覺複核。
