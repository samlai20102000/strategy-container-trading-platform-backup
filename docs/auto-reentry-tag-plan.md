# 策略卡片「自動重新入市」視覺標籤規劃報告

## 需求 1: 在策略列表的卡片上新增一個視覺化標籤，用來直觀顯示該策略目前是否已啟用「自動重新入市」功能。

### 1. 功能規劃

**目標:** 提供一個清晰、通用的視覺標籤，讓用戶在策略列表頁面能快速識別每個策略的「自動重新入市」配置狀態。

**核心原則:**
*   **配置狀態優先:** 標籤應反映策略配置中 `reentryEnabled` 的持久化狀態，而非運行時的實時狀態（例如，即使啟用，也可能因市場條件暫時不重新入市）。這符合用戶「感覺不到系統有開了」的疑問，因為他期望看到的是配置層面的確認。
*   **通用性:** 雖然目前 KAMA 彩虹馬丁策略有 `reentryEnabled` 屬性，但其他策略的重新入市邏輯可能隱藏在各自的 `vXXConfig` 內部。為實現通用標籤，需要修改後端 `strategies.list` 查詢，將所有策略的 `reentryEnabled` 狀態統一提取並添加到頂層 `Strategy` 物件中。
*   **精確性:** 標籤應能區分不同策略類型（例如 KRM、V4.1 等）的重新入市邏輯，並在工具提示中提供簡要說明。

**功能細節:**
1.  **後端數據統一:**
    *   修改 `server/routers.ts` 中的 `strategies.list` 查詢，為每個返回的 `Strategy` 物件添加一個頂層的 `reentryEnabled` 屬性。
    *   這個屬性將根據不同策略的配置類型（`kamaRainbowMartinConfig`、`v41Config`、`v35Config` 等）從其內部配置中提取 `reentryEnabled` 或等效的重新入市開關狀態。
    *   如果某策略沒有明確的重新入市配置，則預設為 `false`。
2.  **前端數據綁定:**
    *   `client/src/pages/Strategies.tsx` 中的策略卡片將直接使用這個統一的 `s.reentryEnabled` 屬性來渲染標籤。

### 2. UI 設計

**位置:**
*   沿用 KAMA 彩虹馬丁策略現有的徽章位置 (`Strategies.tsx` 的 1358-1367 行附近)，在策略名稱和交易對徽章旁邊。
*   這確保了視覺上的一致性，並利用了現有佈局空間。

**樣式:**
*   使用 `Badge` 組件，保持與現有策略狀態徽章（運行中、已暫停、已停止）相似的視覺風格。
*   **啟用狀態:** 使用綠色或藍色調（例如 `bg-emerald-500/15 text-emerald-400 border-emerald-500/30` 或 `bg-sky-500/15 text-sky-400 border-sky-500/30`），顯示文字為「自動重入：開啟」。
*   **停用狀態:** 使用灰色調（例如 `bg-zinc-500/15 text-zinc-400 border-zinc-500/30`），顯示文字為「自動重入：關閉」。

**工具提示 (Tooltip):**
*   為「自動重入」徽章添加工具提示，當用戶鼠標懸停時顯示更詳細的資訊。
*   **通用提示:** 「此狀態來自策略配置，指示策略在平倉後是否會根據條件自動重新入市。」
*   **策略特定提示 (可選，但可增強實用性):** 根據策略類型，可以在工具提示中加入更具體的重新入市條件，例如：
    *   KAMA 彩虹馬丁: 「基於 KAMA 趨勢方向，同方向平倉後自動重新入市。」
    *   V4.1: 「基於三 K 形態與 KAMA 方向鎖，同方向平倉後自動重新入市。」

### 3. 實作步驟

1.  **修改 `server/routers.ts`:**
    *   在 `strategiesRouter.list` 的 `items.map((s) => { ... })` 邏輯中，根據 `s.strategyKey` 判斷策略類型。
    *   從 `s.martinState` 或 `s.vXXConfig` 中提取 `reentryEnabled` 或等效的布林值。
    *   將提取到的值作為 `reentryEnabled` 屬性添加到返回的策略物件 `s` 中。
    *   確保所有策略類型都有明確的 `reentryEnabled` 來源或預設值。
2.  **修改 `client/src/pages/Strategies.tsx`:**
    *   找到策略卡片渲染部分（約 1347 行）。
    *   將現有的 KRM 專屬 `reentryEnabled` 徽章邏輯泛化，使其適用於所有策略。
    *   使用 `s.reentryEnabled` 屬性來條件渲染徽章的文字和樣式。
    *   為徽章添加 `title` 屬性或使用 `Tooltip` 組件來顯示詳細說明。
3.  **測試:**
    *   新增或修改單元測試，確保後端 `strategies.list` 正確返回 `reentryEnabled` 屬性。
    *   進行前端視覺驗證，確認所有策略卡片都能正確顯示「自動重入」標籤，且樣式和工具提示符合預期。

## 需求 2: 最大回撤 100% 問題與優化建議 (排查回測中心數據準確性)

### 1. 問題分析

用戶回報回測 UI 顯示「-100% 最大回撤」，但 CSV 數據顯示實際最大單筆虧損僅為 -1.82 USDT，累積回撤為 -3.05%。這強烈暗示 UI 顯示存在錯誤或誤導。

**初步判斷:**
*   **UI 顯示錯誤:** `client/src/components/backtest/BacktestReport.tsx` 中，`maxDrawdown` 和 `maxDrawdownUSDT` 可能被錯誤地格式化或計算。特別是 `-{metrics.maxDrawdown}%` 的無條件負號，可能導致正值回撤被顯示為負值，或負值回撤被加倍負號。
*   **數據計算邏輯問題:** 儘管 CSV 數據看起來正常，但仍需排查後端計算 `maxDrawdown` 的邏輯，確保其定義與業界標準一致（通常指從峰值到谷底的資產淨值下降百分比）。

### 2. 排查規劃

1.  **前端 UI 渲染邏輯排查:**
    *   **文件:** `client/src/components/backtest/BacktestReport.tsx`。
    *   **目標:** 檢查 `maxDrawdown` 和 `maxDrawdownUSDT` 的渲染邏輯，特別是負號的處理。確認是否在 UI 層面無條件添加了負號，導致數據顯示異常。
    *   **行動:** 閱讀相關代碼行（約 473-505 行），並測試修改渲染方式以觀察效果。
2.  **後端數據計算邏輯排查:**
    *   **文件:** 需要定位計算回測指標的後端服務或函數。根據上下文，可能在 `server/routers/backtest.router.ts` 或其調用的 `server/services` 相關文件中。
    *   **目標:** 理解 `maxDrawdown` 的計算方式。確認其是否正確反映了從資產淨值峰值到谷底的最大百分比跌幅。
    *   **行動:** 搜尋 `maxDrawdown` 關鍵字，追溯其計算源頭，並與業界標準定義進行比對。

### 3. 優化建議

1.  **修復 UI 顯示:** 根據排查結果，修正 `BacktestReport.tsx` 中的渲染邏輯，確保 `maxDrawdown` 顯示正確的符號和數值。
2.  **澄清回撤定義:** 在 UI 或文檔中明確解釋「最大回撤」的計算方式，避免用戶誤解。
3.  **增加風險指標:** 考慮增加其他風險指標，例如「最大單筆虧損百分比」、「平均虧損」等，提供更全面的風險視圖。

## 需求 3: 全面排查回測中心對應不同策略的所有回測功能和數據計算

### 1. 問題分析

用戶對回測中心的數據準確性表示擔憂，並強調其對部署決策的重要性。這是一個全面的質量保證需求。

### 2. 排查規劃

這將是一個系統性的排查工作，需要覆蓋回測流程的各個環節。

1.  **數據輸入與預處理:**
    *   **文件:** 涉及回測數據加載和策略配置解析的相關文件。
    *   **目標:** 確保歷史數據加載正確，且策略參數（如 KAMA 線、馬丁層、止損止盈等）能被回測引擎正確解析和應用。
2.  **回測引擎核心邏輯:**
    *   **文件:** 涉及實際模擬交易執行的核心文件。這可能是一個獨立的服務或 `server/services` 中的模塊。
    *   **目標:** 審查交易模擬、訂單撮合、倉位管理、資金計算等核心邏輯，確保其符合實際交易所行為。
    *   **特別關注:**
        *   **重新入市邏輯:** 結合需求 1 的排查，確認回測引擎中「自動重新入市」的觸發條件和執行效果是否與策略配置一致。
        *   **馬丁格爾層級管理:** 確保馬丁格爾的加倉、平倉、層級計算等邏輯正確無誤。
        *   **止損止盈:** 確認硬止損、移動止盈等風險控制機制在回測中正確觸發。
3.  **指標計算:**
    *   **文件:** 涉及所有回測指標計算的服務或函數。
    *   **目標:** 逐一審查所有關鍵指標（總收益、勝率、夏普比率、利潤因子、最大回撤等）的計算公式，確保其數學正確性與業界標準一致。
    *   **行動:** 對每個指標，手動計算幾個典型案例，與回測結果進行比對。
4.  **結果輸出與持久化:**
    *   **文件:** 涉及回測結果保存到數據庫和生成 CSV/JSON 報告的文件。
    *   **目標:** 確保計算出的指標能正確保存，並在前端 UI 和導出報告中正確呈現。
5.  **不同策略類型兼容性:**
    *   **文件:** 涉及不同策略配置解析和執行的文件。
    *   **目標:** 確保回測中心能正確處理所有已支持的策略類型（KRM、V4.1、V2.5 等），且其特有邏輯（如 KRM 的 KAMA 線、V4.1 的三 K 形態）在回測中得到正確模擬。

### 3. 優化建議

1.  **單元測試與集成測試:** 為回測引擎的核心邏輯和指標計算添加全面的單元測試和集成測試，確保每次代碼修改後數據準確性不受影響。
2.  **回測報告詳盡化:** 考慮在回測報告中增加更多詳細信息，例如：
    *   **交易日誌:** 每次開平倉的詳細記錄，包括時間、價格、數量、P&L 等。
    *   **資金曲線:** 視覺化展示資產淨值隨時間的變化。
    *   **風險指標細分:** 更多關於風險分佈、虧損連續性等指標。
3.  **性能優化:** 對於大規模回測，優化回測引擎的性能，確保快速生成結果。
4.  **用戶可配置性:** 允許用戶在回測時配置更多選項，例如滑點、手續費等，使回測結果更接近實盤。
