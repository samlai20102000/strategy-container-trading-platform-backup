# OKX 訂單與手續費截圖稽核筆記

## 圖片 1：歷史委託（前兩個水平裁切區）

原圖尺寸為 2245 × 734，依左至右四個重疊區塊檢視。

第一區可確認共有四筆 BTCUSDT 永續、全倉 5x 交易：2026/07/31 15:44:08 買入平空、15:30:34 賣出開空、14:47:50 買入平空、13:48:40 賣出開空。

第二區的「成交均價｜委託價」顯示：15:44:08 為成交均價 63,875.6、委託價 63,891.7；15:30:34 為成交均價 63,932、委託價明示「市價」；14:47:50 為成交均價 64,176.1、委託價 64,185.6；13:48:40 為成交均價 64,237.8、委託價明示「市價」。每筆成交／委託總量均為 0.0046 BTC。

目前可直接證明兩筆「賣出開空」是市價委託；兩筆「買入平空」是有限價的委託，但仍需檢查後續欄位才能判斷其手續費率。僅有 `limit` 並不保證 maker；若限價跨過對手價立即成交，仍可成為 taker。

第三、四區可確認四筆成交價值與手續費：293.53 USDT 對應 0.14691388 USDT、293.79 USDT 對應 0.1470436 USDT、294.91 USDT 對應 0.14760524 USDT、295.19 USDT 對應 0.14774673 USDT。兩筆平空收益分別為 +0.25 USDT（+0.44%）與 +0.28 USDT（+0.48%）。

注意：畫面手續費約為成交價值的 **0.05%**，不是 0.5%；例如 0.1469 ÷ 293.53 ≈ 0.0005，即 0.05%。四筆費率都落在約 0.05%，其中兩筆明示市價，另兩筆雖有委託價但仍按相同 taker 級別收費，符合「普通 limit 因穿價立即成交，未被 post-only 保證為 maker」的現象。

## OKX 官方規則核對

OKX 官方《Trading Fee Rules FAQ》（2026-07-20 更新）明確說明：費率取決於**實際成交是 maker 還是 taker**，不是只看訂單名稱；普通限價單若立即與簿上訂單成交，仍按 taker 收費。官方《Basic Order Types》（2026-06-29 更新）則說明：`Post Only` 才保證訂單進入委託簿成為 maker；若提交時會立即撮合，交易所會取消該單。

## 系統設定與資料庫交叉核對

策略設定截圖在擷取當下，欄位本身顯示「市價單」，展開選單中的勾號亦在「市價單」；「限價單（用訊號價格）」只是被游標高亮，畫面本身不能證明當下已選取或已保存限價。這不代表使用者之後沒有改成限價，但必須區分截圖時點。

2026-07-31 以唯讀 SQL 核對目前資料庫，四個實際策略均已保存 `orderType=limit` 且 `enabled=1`：`strategy_20415`、`20415_KAMA_MARTIN_V35`、`RAINBOW_TREND_LADDER_V1`、`KAMA_3K_HF_V61`。因此目前問題不能只歸因於 UI；通用執行器多個策略分支仍硬編碼 `market`，而一般 `limit` 即使送出也可能因價格穿越委託簿成為 taker。
