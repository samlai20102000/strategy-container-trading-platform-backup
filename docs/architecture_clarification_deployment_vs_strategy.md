# 架構澄清：「部署管理」vs「策略交易新增策略」的本質區別

## 問題陳述

用戶提出疑問：「部署管理」面板的功能（搜尋、篩選、部署卡片、編輯配置等）是否與「策略交易新增策略」的功能重複？

這是一個非常有洞察力的問題，涉及系統架構的核心設計。本文將詳細澄清兩者的本質區別，並提出優化方案以避免功能重複。

---

## 1. 核心概念區分

### 1.1 策略（Strategy）vs 部署（Deployment）

**策略（Strategy）**：
- **定義**：一個交易策略的「配置模板」或「策略實例」。
- **生命週期**：創建 → 編輯 → 保存 → 刪除。
- **狀態**：草稿、已保存、已發佈等。
- **用途**：存儲策略的配置參數（例如 KAMA 參數、馬丁層級、風控設置等），但**不涉及實盤執行**。
- **示例**：「KAMA 3K V6.1 高頻 - 版本 A」（一個配置模板）。

**部署（Deployment）**：
- **定義**：一個「正在運行或曾經運行過的策略實例」，綁定了具體的 API Key、交易對、部署模式（S1/M2/H3）等。
- **生命週期**：創建 → 啟動 → 運行中 → 暫停 → 恢復 → 停止 → 已封存。
- **狀態**：草稿、已創建、運行中、暫停、停用、已封存等。
- **用途**：實際執行策略，與交易所交互，生成訂單、持倉、日誌等。
- **示例**：「部署 #240004：KAMA 3K V6.1 高頻 - BTC-USDT - M2 模式 - 運行中」（一個正在運行的實例）。

### 1.2 關鍵區別總結表

| 維度 | 策略（Strategy） | 部署（Deployment） |
|------|-----------------|-------------------|
| **定義** | 配置模板 | 運行實例 |
| **綁定 API Key** | ❌ 否 | ✅ 是 |
| **綁定交易對** | ❌ 否 | ✅ 是 |
| **綁定部署模式** | ❌ 否（或預設） | ✅ 是（S1/M2/H3） |
| **實盤執行** | ❌ 否 | ✅ 是 |
| **生成訂單** | ❌ 否 | ✅ 是 |
| **運行狀態** | 草稿/已保存 | 運行中/暫停/停用 |
| **操作** | 編輯、複製、刪除 | 啟動、暫停、停止、編輯配置 |

## 2. 「策略交易新增策略」的功能定位

### 2.1 當前功能

「策略交易新增策略」是一個**策略配置面板**，用於：

1. **選擇策略類型**（例如 KAMA 3K V6.1）。
2. **配置策略參數**（例如 KAMA 參數、馬丁層級、風控設置）。
3. **選擇部署模式**（S1/M2/H3）。
4. **保存策略配置**到數據庫。

**關鍵點**：此時**還未綁定 API Key 和交易對**，因此**還未創建部署**。

### 2.2 用戶流程

```
策略交易新增策略
  ↓
1. 選擇策略類型（KAMA 3K V6.1）
  ↓
2. 配置策略參數（KAMA 參數、馬丁層級等）
  ↓
3. 選擇部署模式（S1/M2/H3）
  ↓
4. 保存策略配置
  ↓
策略已保存（但尚未部署）
  ↓
（可選）在部署工作台中基於此策略創建部署
```

## 3. 「部署管理」面板的功能定位

### 3.1 當前功能

「部署管理」面板是一個**部署實例管理面板**，用於：

1. **列出所有部署實例**（已創建、運行中、暫停、停用等）。
2. **搜尋和篩選部署**（按名稱、策略、交易對、模式、狀態）。
3. **查看部署詳情**（API Key、交易對、部署模式、運行狀態、性能指標等）。
4. **管理部署生命週期**（啟動、暫停、停止、編輯配置、複製、刪除）。
5. **執行 Preflight 檢查**（驗證部署配置是否有效）。

**關鍵點**：此時**已綁定 API Key 和交易對**，**已創建部署實例**，**可以實盤執行**。

### 3.2 用戶流程

```
部署工作台 - 快速啟動面板
  ↓
1. 選擇策略（例如已保存的 KAMA 3K V6.1 配置）
  ↓
2. 選擇 API Key（例如 OKX 帳戶）
  ↓
3. 選擇交易對（例如 BTC-USDT）
  ↓
4. 選擇部署模式（S1/M2/H3）
  ↓
5. 啟動部署
  ↓
部署已創建並運行中
  ↓
部署管理面板
  ↓
1. 列出該部署（#240004：KAMA 3K V6.1 - BTC-USDT - M2 - 運行中）
  ↓
2. 可以暫停、停止、編輯配置、查看日誌等
```

## 4. 為什麼不會重複？架構設計原理

### 4.1 層級分離原則

系統採用**三層架構**：

```
┌─────────────────────────────────────────────────────────┐
│ 層級 1：策略配置層（Strategy Configuration Layer）     │
├─────────────────────────────────────────────────────────┤
│ 功能：定義、編輯、保存策略配置                           │
│ 位置：策略交易模組                                       │
│ 操作：新增、編輯、複製、刪除策略                         │
│ 數據：策略參數（KAMA 參數、馬丁層級等）                 │
│ 實盤執行：❌ 否                                          │
└─────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────┐
│ 層級 2：部署創建層（Deployment Creation Layer）        │
├─────────────────────────────────────────────────────────┤
│ 功能：基於策略配置 + API Key + 交易對創建部署實例       │
│ 位置：部署工作台 - 快速啟動面板                         │
│ 操作：選擇策略、API Key、交易對、模式 → 創建部署        │
│ 數據：部署實例（deploymentId、apiKeyId、symbol 等）    │
│ 實盤執行：❌ 否（但已準備好執行）                       │
└─────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────┐
│ 層級 3：部署管理層（Deployment Management Layer）      │
├─────────────────────────────────────────────────────────┤
│ 功能：管理已創建的部署實例的生命週期                     │
│ 位置：部署工作台 - 部署管理面板                         │
│ 操作：啟動、暫停、停止、編輯、查看日誌等                │
│ 數據：部署狀態、運行日誌、性能指標等                     │
│ 實盤執行：✅ 是                                          │
└─────────────────────────────────────────────────────────┘
```

### 4.2 數據流向

```
策略交易新增策略
  ↓ 保存策略配置
  ↓
Strategy 表
  ├─ id: 1
  ├─ name: "KAMA 3K V6.1 高頻"
  ├─ config: { kamaParam, martinLayers, ... }
  ├─ deploymentMode: "S1" (預設或用戶選擇)
  └─ ...
  ↓
部署工作台 - 快速啟動面板
  ├─ 選擇策略 (Strategy.id = 1)
  ├─ 選擇 API Key (ApiKey.id = 5)
  ├─ 選擇交易對 (symbol = "BTC-USDT")
  ├─ 選擇部署模式 (deploymentMode = "M2")
  ↓ 創建部署
  ↓
Deployment 表
  ├─ id: "deployment_240004"
  ├─ strategyId: 1 (關聯策略)
  ├─ apiKeyId: 5 (綁定 API Key)
  ├─ symbol: "BTC-USDT" (綁定交易對)
  ├─ deploymentMode: "M2" (部署模式)
  ├─ status: "ACTIVE"
  └─ ...
  ↓
部署管理面板
  ├─ 列出部署 #240004
  ├─ 顯示完整信息（策略、API Key、交易對、模式、狀態等）
  ├─ 提供管理操作（啟動、暫停、停止等）
  ↓
實盤執行引擎
  ├─ 讀取部署配置
  ├─ 根據部署模式執行策略
  ├─ 生成訂單、更新持倉
  └─ ...
```

## 5. 優化方案：避免功能重複

### 5.1 現有設計中的潛在重複

如果「部署管理」面板提供了**完整的策略配置編輯功能**（例如修改 KAMA 參數、馬丁層級等），那麼確實會與「策略交易新增策略」重複。

### 5.2 優化設計：功能邊界清晰化

**「策略交易新增策略」應提供**：
- ✅ 策略配置的完整編輯（KAMA 參數、馬丁層級、風控設置等）
- ✅ 策略的保存、複製、刪除
- ✅ 部署模式的預設選擇（但不涉及 API Key 和交易對）
- ✅ 策略的版本管理

**「部署管理」面板應提供**：
- ✅ 部署實例的列表、搜尋、篩選
- ✅ 部署實例的生命週期管理（啟動、暫停、停止）
- ✅ 部署實例的運行狀態、日誌、性能指標
- ⚠️ **有限的配置編輯**（僅允許修改部署特有的參數，例如風控門檻、停止損失等，但**不允許修改策略的核心參數**）
- ❌ 不提供策略的完整編輯（應跳轉到策略交易模組）

### 5.3 「部署管理」面板中的配置編輯限制

當用戶點擊「編輯配置」時，系統應區分：

1. **策略核心參數**（KAMA 參數、馬丁層級等）：
   - 顯示為**只讀**或**灰色**。
   - 提供「編輯策略」按鈕，跳轉到策略交易模組。
   - 提示：「要修改策略參數，請在策略交易模組中編輯對應的策略配置」。

2. **部署特有參數**（例如風控門檻、停止損失、通知設置等）：
   - 允許編輯。
   - 修改後立即應用到部署。

**UI 示例**：

```
部署詳情 - 編輯配置

策略配置（只讀）
├─ KAMA 參數
│  ├─ 快線週期: 5 [只讀]
│  ├─ 慢線週期: 34 [只讀]
│  └─ [編輯策略] ← 跳轉到策略交易
├─ 馬丁層級
│  ├─ 層 1: 1.5x [只讀]
│  ├─ 層 2: 1.5x [只讀]
│  └─ ... [只讀]
│  └─ [編輯策略] ← 跳轉到策略交易

部署特有參數（可編輯）
├─ 風控門檻: 4% [可編輯]
├─ 停止損失: 2% [可編輯]
├─ 通知設置: [可編輯]
└─ [保存]
```

### 5.4 改進的用戶流程

**場景 1：用戶想修改策略參數**

```
部署管理面板
  ↓ 點擊「編輯配置」
  ↓
部署詳情 - 編輯配置
  ↓ 發現策略參數是只讀的
  ↓ 點擊「編輯策略」
  ↓
策略交易模組
  ↓ 編輯策略參數
  ↓ 保存
  ↓
策略已更新，所有基於此策略的部署將使用新配置
```

**場景 2：用戶想調整部署的風控門檻**

```
部署管理面板
  ↓ 點擊「編輯配置」
  ↓
部署詳情 - 編輯配置
  ↓ 修改「風控門檻」
  ↓ 點擊「保存」
  ↓
部署已更新，新的風控門檻立即生效
```

## 7. 結論

「部署管理」面板與「策略交易新增策略」**不會重複**，因為它們在系統架構中扮演不同的角色：

- **策略交易新增策略**：定義「策略配置模板」（What）。
- **部署工作台快速啟動**：決定「在哪裡、用哪個帳戶運行」（Where & How）。
- **部署管理面板**：管理「正在運行的部署實例」的生命週期（Manage）。

通過清晰的功能邊界與層級分離，系統既避免了功能重複，又提供了完整的用戶體驗。
