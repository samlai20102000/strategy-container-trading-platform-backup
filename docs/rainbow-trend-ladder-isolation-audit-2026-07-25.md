# 七彩虹線趨勢跟蹤階梯馬丁策略：隔離開發稽核

## 任務與金融風險邊界

本策略是全新的獨立策略實體，僅以 20415 七彩虹馬丁的架構、功能整合與 UI 版型作為只讀複製基線。20415 專屬程式不得修改；新策略預設不建立部署、不啟用、不發送訂單、不平倉，也不共用 20415 的設定、狀態、租約鎖、部署 ID 或策略 key。所有真實交易啟用均須在模擬盤驗證完成後，由使用者另行明確決定。

> 金融風險提示：本系統為自動交易軟體實作，不構成保證獲利。馬丁加倉可能快速放大曝險；任何實盤啟用前必須完成模擬盤、極端行情與交易所規格驗證。

## 已確認的整合面

`server/services/strategyStudio.ts` 以 `BUILT_IN_KEYS` 保護內建策略，並在 `initStrategyStudio()` 顯式註冊。新策略必須使用全新 key、全新 class，加入白名單與註冊序列；不得替換 `Strategy20415`。

`server/services/executor.ts` 對 `strategy_20415` 有專屬 `executeSignalRainbow20415` 管線。新策略不能落入通用引擎，也不能共用這個函式；必須有新 key 的同級專屬分派與新核心型別，所有狀態轉移仍須等交易所成功回報後才持久化。

## 排程與執行架構

| 方案 | 運作方式 | 取捨 | 採用狀態 |
|---|---|---|---|
| 每分鐘受管理的 HTTP 心跳 | 每分鐘呼叫一次部署站的冪等處理器；狀態保存在資料庫；不依賴常駐記憶體 | 最符合目前 Autoscale 託管與既有平台架構；最低干擾 | 作為本輪程式設計目標，但不在未經模擬驗證前建立或啟用新排程 |
| 24×7 單一常駐程序 | 一個持續運行的程序以次分鐘延遲監控 | 無冷啟動、適合更低延遲，但需要常駐託管並增加營運成本 | 本規格最低頻率為每分鐘，暫不需要 |

本輪禁止新增 `setInterval`、`node-cron` 或其他依賴程序常駐的計時器。M30 收盤訊號與每分鐘持倉管理應由同一個新策略專屬、可重試且冪等的週期處理路徑完成；部署後仍保持新策略停用，避免任何交易副作用。

## 回滾與緊急處置

目前資料庫中的新策略部署數為 0，因此此版本若不建立新策略，不需要任何交易回滾。若未來已建立但尚未持倉，回滾順序應為：**停用新策略 → 取消新策略專屬 Heartbeat（如有）→ 確認無未完成訂單／持倉 → 刪除或保留停用部署 → 回復上一個已知穩定檢查點**。所有操作只以 `RAINBOW_TREND_LADDER_V1` 與其部署 ID 為範圍。

若新策略已有持倉，禁止直接做帳戶級 close-all。應先鎖定新策略、停止新進場，核對本地成交與交易所持倉能唯一證明所有權後，再使用新策略專屬 KILL 處置；若持倉所有權不唯一，必須停止自動操作並由使用者人工核對。回滾後需再次驗證原 `strategy_20415` 的 key、雜湊、部署 ID、啟用狀態與執行日誌均未變。

| 回滾層級 | 操作 | 20415 保護條件 |
|---|---|---|
| UI／設定 | 停用或移除新部署 | 不編輯 20415 表單或快照 |
| 排程 | 只取消新部署的 Heartbeat UID | 不碰 20415 的 UID／租約 |
| 倉位 | 僅在可證明所有權時執行新策略 KILL | 禁止帳戶級全部平倉 |
| 程式版本 | 回復本輪發布前的穩定 checkpoint | 回復後重新跑 20415 雜湊測試 |
| 稽核 | 比對 signals、heartbeat logs 與交易所訂單 | 以新 key／新部署 ID 過濾，不混入 20415 |
