# Kama 彩虹馬丁三模式契約 v2（實作基線）

## 已由用戶確認的業務語義

1. **S1 是主循環與主持倉。**
2. **M2 是 S1 的輔助反向腿。** 只有在同一個 S1 cycle 仍持倉且目前有浮動虧損，並且 Kama 彩虹馬丁原本的入場判定出現與 S1 相反的有效訊號時，才可開啟一條 M2 反向腿。
3. 同一個 S1 cycle 最多只能開啟一條 M2；其後再出現相反訊號，不得建立第二條 M2。新的 S1 cycle 才可重新取得一次 M2 開腿資格。
4. **M2 使用獨立且全新的馬丁腿狀態。** M2 開腿不得繼承 S1 的 `currentLayer`、最後加倉價或 trailing 狀態；其底倉從該腿初始狀態建立，之後第一次合法馬丁加倉必須從該腿的第一個配置層級開始，不能跳到 S1 的既有層級。
5. **H3 是 S1 的自動保護對沖腿。** 當同一個 S1 cycle 的浮虧達到策略既有、可版本化的 X% 閾值時自動建立一條反向 H3；不需要等待相反入場訊號。H3 保護腿禁止馬丁加倉。
6. M2 或 H3 開腿時，S1 不得因此平倉；主腿與輔助腿同時存在。
7. S1、M2、H3 使用同一策略資金池及同一 gross／margin 上限，資金核准優先次序為 S1 → M2 → H3。共享資金不代表共享腿級持倉狀態；每條腿仍須有獨立的數量、均價、已實現／未實現盈虧與開平倉原因。
8. 回測、實盤、新建策略與參數快照導入必須經同一版本化 canonical policy 正規化流程。
9. 回測報告每筆交易必須包含部署模式與實際腿來源，固定映射為 `PRIMARY → S1`、`INDEPENDENT → M2`、`HEDGE → H3`，並保留 `cycleId`、`legId`、觸發／退出原因，使逐筆資料可重算 UI 的已實現盈虧、未實現盈虧、最終權益及總回報。

## 不得擅自假設的語義

- 用戶尚未確認 M2／H3 的獨立退出門檻或「S1 恢復盈利 X% 即平腿」規則。
- 報告中的馬丁層級必須反映每條腿自己的真實策略狀態；不得把 S1 的層級帶入 M2，也不得為了顯示效果事後重編號。
- 修復後 M2／H3 的交易筆數與收益不可預估；只能由相同資料、參數與明確事件追蹤重新回測得出。
- 本契約目前只改變 Kama 彩虹馬丁語義；共用報告欄位可供未來策略使用，但不得無確認地改寫其他策略的 M2／H3 行為。

## 目前已確認的代碼差異

- `shared/executionModes.ts` 的一般 M2 目前描述為 LONG／SHORT 完全獨立，與 Kama 彩虹馬丁「依附同一 S1 cycle 的單次輔助腿」不同。
- 一般 H3 目前強制 `requireOppositeSignal: true`，與用戶確認的 Kama 彩虹馬丁「達 X% 浮虧即自動建立」不同。
- `shared/strategies/kamaRainbowMartinExecutionPolicy.ts` 目前將 KRM H3 閾值固定為 4%，這是既有 canonical 值；是否改成 UI 可調必須由版本化 policy 與快照相容測試決定，不能散落硬編碼。

## 安全驗證限制

- 所有測試、回放及 UI 驗收不得呼叫真實 `placeOrder`、`cancelOrder`、`closePositionSmart` 或建立可送往交易所的實盤 order intent。
- 實盤路徑若缺少 S1 cycle、腿 ownership、資金快照、交易所能力或精確平倉數量，必須 fail closed。
